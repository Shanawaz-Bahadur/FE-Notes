Q) Shallow copy and deep copy
Ans) A shallow copy creates a new object but only copies the memory addresses of its nested objects, meaning both the original and copy share the same inner data.
    A deep copy creates a fully independent clone, recursively duplicating both the main object and all nested data so nothing is shared

    Example: 
    
    import copy

    original_list = [[1, 2], 3]

    # --- Shallow Copy ---
    shallow_copied = copy.copy(original_list)
    shallow_copied[0][0] = 99  # Mutates the nested list
    # original_list also becomes [[99, 2], 3]

    # --- Deep Copy ---
    deep_copied = copy.deepcopy(original_list)
    deep_copied[0][0] = 55  # Mutates the nested list, as it doesn't change the value of the original list
    # original_list remains [[99, 2], 3]

Q) pass by value and pass by reference?
Ans) 
    1. Immutable Objects (Acts like Pass-by-Value)
        When you pass an immutable object, the function receives the reference. However, because the object cannot be changed, any attempt to modify it forces Python to create a new object in memory and bind the local variable name to it.

            def modify_number(num):
                # This creates a NEW integer object 15.
                # The local variable 'num' now points to 15.
                num += 10 
                print("Inside function:", num) # 15

            x = 5
            modify_number(x)
            print("Outside function:", x) #  5

    2. Mutable Objects (Acts like Pass-by-Reference)
        When you pass a mutable object, the function receives the same reference to the exact same object. If you modify that object in-place (like appending to a list), the changes will reflect outside the function.

            def modify_list(my_list):
                # This modifies the original shared object in memory
                my_list.append(4)
                print("Inside function:", my_list) # [1, 2, 3, 4]

            numbers = [1, 2, 3]
            modify_list(numbers)
            print("Outside function:", numbers) # [1, 2, 3, 4]

    - The Crucial Catch: Reassignment Detaches the Reference
        Even with mutable objects, if you reassign the variable inside the function using the = operator, you break the link to the original object. You are pointing the local variable to a brand new object.

        def reassign_list(my_list):
            # Reassignment breaks the link. 
            # 'my_list' now points to a completely separate list.
            my_list = [100, 200] 
            print("Inside function:", my_list) # [100, 200]

        numbers = [1, 2, 3]
        reassign_list(numbers)
        print("Outside function:", numbers) # [1, 2, 3]

Q) What is public, private and protected?
Ans) Python does not have strict public, private, or protected keywords like Java or C++. Instead, it relies on naming conventions using underscores to signal how variables and methods should be accessed for the developer. 

    1. Public Access Modifier
        By default, every variable and method defined in a Python class is public. They can be modified and accessed from inside or outside the 
        Example: 
            class Account:
                def __init__(self, username):
                    self.username = username  # Public attribute

            acc = Account("Alice")
            print(acc.username)  # Works: accessible from outside

    2. Protected Access Modifier
        You can declare a protected member by adding a single leading underscore (_) to its name. This is purely an honorable agreement among developers. Python will not stop you from accessing it outside the class, but doing so violates standard coding practices.
        Example: 
            class Account:
                def __init__(self):
                    self._database_id = 4502  # Protected by convention

            acc = Account()
            print(acc._database_id)  # Works, but discouraged by community standards

    3. Private Access Modifier and Name Mangling(***As in Python we don't have strict data hiding as we have in c++ and Java)
        You can declare a private member by adding a double leading underscore (__) to its name. Python uses a mechanism called Name Mangling to protect these fields. It automatically changes the internal variable name behind the scenes, making a direct call fail with an AttributeError.
        Example:
            class Account:
                def __init__(self, PIN):
                    self.__pin = PIN  # Private attribute

            acc = Account(1234)
            # print(acc.__pin)  # Fails! Raises AttributeError

        -- ***How to Bypass Name Mangling
            Python renames the private attribute internally to the format _ClassName__variableName. If you absolutely need to access it from the outside for debugging, you can use that mangled format:
            Example:
                # Accessing the private member via its mangled name
                print(acc._Account__pin)  # Works: Outputs 1234

    Q) What is Diamond problem?
    Ans) The diamond problem (or "Deadly Diamond of Death") is an ambiguity that arises in multiple inheritance when a subclass inherits from two parent classes that share a common grandparent class
        Python resolves this conflict completely and predictably using a mechanism called Method Resolution Order (MRO), meaning the diamond problem does not break your code like it does in some other languages.

    Python's Solution: MRO(Method Resolution Order): Python searches for attributes and methods from left to right, then bottom to top.

    Example: Here is how Python predictably prioritizes the left-most parent during a method execution conflict
        class A:
            def action(self):
                print("Action from A")

        class B(A):
            def action(self):
                print("Action from B")

        class C(A):
            def action(self):
                print("Action from C")

        # D inherits from B first, then C
        class D(B, C):
            pass

        obj = D()
        obj.action()  # Output: Action from B

        # Let's inspect the resolution chain
        print(D.__mro__)
        # Output: (<class '__main__.D'>, <class '__main__.B'>, <class '__main__.C'>, <class '__main__.A'>, <class 'object'>)

====> Abstration
    It is a concept that hides complex implementation details and only exposes essential features to the user.

    Core Implementation: Python does not provide built-in abstract classes natively, but it achieves abstraction via the standard ⁠abc module.
    
        - ABC Class: The base class that you inherit from to mark a class as abstract.
        - @abstractmethod: A decorator used to declare methods that must be overridden by child classes.

    -- Rules of Abstraction
    
        - No Direct Instantiation: You cannot create an object directly from an abstract class; doing so raises a TypeError.
        - Enforced Implementation: Any concrete subclass inheriting from an abstract class must implement all of its abstract methods.
        - Mixed Methods: Abstract classes can contain both abstract methods (empty) and concrete methods (fully implemented code for reusability).
    
    Example:
        from abc import ABC, abstractmethod
        # Abstract Base Class (The Blueprint)
        class Vehicle(ABC):
            
            @abstractmethod
            def start_engine(self):
                """Abstract method; no implementation logic here."""
                pass

            def honk(self):
                """Concrete method; shared directly by all subclasses."""
                return "Beep beep!"

        # Concrete Subclass 1
        class Car(Vehicle):
            def start_engine(self):
                return "Car engine turns over: Vroom!"

        # Concrete Subclass 2
        class Motorcycle(Vehicle):
            def start_engine(self):
                return "Motorcycle engine sparks: Braap!"

        # --- Execution ---
        # my_vehicle = Vehicle()  # RAISES TYPEERROR: Can't instantiate abstract class

        car = Car()
        motorcycle = Motorcycle()

        print(car.start_engine())      # Output: Car engine turns over: Vroom!
        print(motorcycle.honk())       # Output: Beep beep! (Inherited concrete method)

Q) What is Exception handling in python?
Ans) Exception handling in Python is a mechanism used to manage runtime errors gracefully, preventing your application from crashing unexpectedly. While syntax errors stop a program before it even runs, exceptions occur during program execution when syntactically correct code encounters an issue, like dividing by zero or trying to open a missing file.Python handles these events using a structured system of try, except, else, and finally blocks.

    Core Keywords and Syntax: The full structure of an exception handler utilizes four distinct blocks:
        - try: Wraps the code that might trigger an error.
        - except: Contains the code that executes if an exception occurs in the try block.
        - else: Runs code only if the try block executed completely without any errors.
        - finally: Executes always, regardless of whether an exception was raised or handled, making it ideal for clean-up tasks like closing files or closing DB connection or any other garbage collection

    Example:
        try:
            # Code that might cause an exception
            file = open("data.txt", "r")
            content = file.read()
            result = 10 / int(content)
        except FileNotFoundError:
            # Handles missing file errors
            print("Error: The file was not found.")
        except ZeroDivisionError:
            # Handles division by zero
            print("Error: Cannot divide by zero.")
        except ValueError:
            # Handles bad data conversion
            print("Error: Invalid data type inside the file.")
        else:
            # Runs only if no exceptions occurred
            print(f"Success! The result is {result}")
        Gentile:
            # Always runs to clean up system resources
            if 'file' in locals() and not file.closed:
                file.close()
            print("Cleanup: File stream closed.")

Q) What is the use of raising the exception though python is raising the exception exception if there is any error found?
Ans) Python only raises exceptions for errors that it can detect automatically. It cannot know your application's ***business rules. The interpreter raises exceptions only for language-level or runtime errors, such as TypeError, IndexError, or ZeroDivisionError. However, it cannot understand application-specific rules like "balance cannot be negative" or "age cannot be be negative." We use raise to enforce these business rules, stop invalid operations, and provide meaningful error messages to the caller.

    Case 1: Interpreter raises the exception
    Python knows this is invalid:

        x = 10 / 0
        Output:
        ZeroDivisionError: division by zero

    Case 2: You raise the exception
    Suppose you're writing a banking application.

        def withdraw(balance, amount):
            return balance - amount

        If:
        withdraw(1000, 2000)

        Python will happily return:
        -1000

        The interpreter doesn't know that a bank account shouldn't have a negative balance. From Python's perspective, subtracting numbers is perfectly valid.

        So you write:

        def withdraw(balance, amount):
            if amount > balance:
                raise ValueError("Insufficient balance")
            return balance - amount

        Now the program enforces your business rule.


Q) What is the use of re-raising thhe exception?
Ans) Re-raising an exception is useful when a function needs to perform some action—such as logging, cleanup, or resource release—but cannot fully handle the error. By using raise inside an except block, we allow the exception to continue propagating to a ***higher level where it can be handled appropriately, while preserving the original traceback for debugging.

Q) How to create a custom exception?
Ans) Simply create a class that inherits from Exception.
    Example:
        class InsufficientBalanceError(Exception):
            pass

        def withdraw(balance, amount):
            if amount > balance:
                raise InsufficientBalanceError("Not enough balance")

        try:
            withdraw(1000, 1500)
        except InsufficientBalanceError as e:
            print(e)

Q) Can a custom exception store additional information?
Ans) Yes
    Example:
        class InvalidAgeError(Exception):
            def __init__(self, age):
                self.age = age
                super().__init__(f"{age} is not a valid age")

        try:
            raise InvalidAgeError(15)
        except InvalidAgeError as e:
            print(e)

    Output:
        15 is not a valid age

Q) Why use with?
Ans) Without with:
        file = open("data.txt", "r")
        content = file.read()
        file.close()    
    If an exception occurs before file.close(), the file may remain open.

    Example:
        file = open("data.txt", "r")
        print(10 / 0)   # Exception occurs
        file.close()    # This line is never executed

    Using with:
        with open("data.txt", "r") as file:
            print(10 / 0)

Ans) Traditionally, __init__.py marks a directory as a Python package. It can also contain package initialization code.

Q) What is __name__?
Ans) __name__ is a special built-in variable that Python automatically sets.

    - If the file is executed directly:
        print(__name__)

    Output: __main__

    - If the file is imported:
        print(__name__)

    Output: demo
    (where demo is the module name).

Q) What is the use of __name__ = "__main__"
Ans) if __name__ == "__main__": is used to ensure that a block of code runs only when the Python file is executed directly, and not when it is imported as a module. Python automatically sets the special variable __name__ to "__main__" for the main script, and to the module's name when imported. This is commonly used to keep test code, examples, or the program's entry point separate from reusable functions and classes.

Q) What is Multiprocessing and Multithreading?
Ans) Multithreading allows multiple threads to run within a single process, sharing the same memory. It is lightweight and ideal for I/O-bound tasks such as API calls, file operations, and database access. However, in CPython, CPU-bound threads are limited by the Global Interpreter Lock (GIL), which prevents multiple threads from executing Python bytecode simultaneously.

Multiprocessing creates multiple independent processes, each with its own memory space and Python interpreter. This avoids the GIL and enables true parallel execution on multiple CPU cores, making it the preferred choice for CPU-intensive tasks such as image processing, machine learning, and large numerical computations.

Q) When to use which?
Ans) 

    Use Multithreading when:
        - Downloading multiple files.
        - Calling multiple APIs.
        - Reading/writing files.
        - Database operations.
        - Web scraping.

    Use Multiprocessing when:
        - Image or video processing.
        - Machine learning.
        - Data analysis.
        - Mathematical computations.
        - Large simulations.

Q) What is the GIL?
Ans)The Global Interpreter Lock (GIL) is a lock in CPython that allows only one thread to execute Python bytecode at a time within a single process.
