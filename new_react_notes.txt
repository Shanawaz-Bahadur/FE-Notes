Q) What is children promps in React ?
Ans) The children prop is a special, built-in property in React that allows you to pass content (text, HTML elements, or other React components) between the opening and closing tags of a component. 

Example:

Q) Why does React need keys?

Q) When is it actually safe to use index as a key?
Ans) 
1. Your items don't have a unique ID (if they do, always use that instead!)
2. The list is completely static - you never add or remove items
3. The list is never reordered or filtered

        Ex: navigation menu links

    If you ever see weird behavior in your lists - like data jumping between items, inputs losing focus, or animations glitching - check your keys first

Q) What is the advantages of giving module.css while creating the css file?
Ans) module.css in React is used to create locally scoped CSS for a component. Normally, CSS is global, so class names can conflict between components. With CSS Modules, React generates unique class names automatically, which helps avoid style collisions.

    Example:

    /* Button.module.css */
        .primary {
        background-color: blue;
        color: white;
        }

    /* JS file */
    import styles from "./Button.module.css";

    function Button() {
    return <button className={styles.primary}>Click Me</button>;
    }

Q) How to send the data from child to parent 
Ans) In React, data is passed from parent to child using props.
But to send data from child to parent, we pass a callback function from the parent to the child, and then call that function from the child component.

Example:
    Parent Component:

        function Parent() {
            const handleData = (data) => {
                console.log(data);
            };
            return <Child sendData={handleData} />;
        }

    Child Component:

        function Child({ sendData }) {

        const handleClick = () => {
            sendData("Hello Parent");
        };

        return <button onClick={handleClick}>Send Data</button>;
        }

Q) Event after updating the state, why the updated value is not immediately available on the next line?
Ans) Because React does not instantly change the state variable.
    Instead, it:

        1. Schedules the update
        2. Re-renders the component
        3. Then provides the new state value

    Example:
        const [cound, setCount] = useState(0)

        const handleClick = () => { 
            console. log("Before setCount, count is: ", count); //0
            setCount(count + 1);
            console. log("After setCount, count is: ", count) ; //0
        }

    Solution:

        1. Use useEffect (Most Common)
            const [count, setCount] = useState(0);

            useEffect(() => {
                console.log("Updated count:", count);
            }, [count]);

            const handleClick = () => {
                setCount(1);
            };

Q) What are the disadvantages of props drilling?
Ans) 1. Reduced Code Maintainability: Intermediate components may receive props that they do not use, just to pass them further down.
     2. Increased Complexity: As the application grows, managing and tracking props across many levels becomes difficult, as in future if project demands to shift some of the component then the path of that props will be disturbed which leads to data leakage
