Q) var vs let vs const?
Ans) 
1. Scope:
    - var
        - Function-scoped (or global if outside a function)
        - Ignores block scope ({})

        if (true) {
            var x = 10;
        }
        console.log(x); // 10 ✅ (still accessible)

    - let and const
        - Block-scoped (limited to {})

        if (true) {
            let y = 20;
        }
        console.log(y); // ❌ ReferenceError

2. Re-declaration

    - var
        - Can be re-declared in the same scope
            var a = 1;
            var a = 2; // ✅ allowed

    - let and const
        - Cannot be re-declared in the same scope
            let b = 1;
            let b = 2; // ❌ Error

3. Re-assignment

    - var and let
        - Can be reassigned

            let c = 5;
            c = 10; // ✅ allowed

    - const
        - Cannot be reassigned

        const d = 5;
        d = 10; // ❌ Error

        ⚠️ But objects/arrays declared with const can still be mutated:

        const obj = { name: "John" };
        obj.name = "Jane"; // ✅ allowed

4. Initialization requirement

    - var and let
        - Can be declared without a value
            -let x;
            
    - const
        - Must be initialized at declaration
            -const x; // ❌ Error

5. Hoisting

    - var
        - Hoisted and initialized as undefined
            - e.g., console.log(a); // undefined
                    var a = 5;

    - let and const
        Hoisted but not initialized
        Exist in a Temporal Dead Zone (TDZ) until declared
            e.g., console.log(b); // ❌ ReferenceError
                  let b = 5;



Q) What is Hoisting?
Ans) Hoisting is JavaScript’s behavior of moving declarations to the top of their scope before code execution. Variables can thus be referred before they are declared in Javascript

    But the behavior differs for:

        - var
        - let
        - const
        - function declarations

    1. var Hoisting

        Variables declared with var are:

        - Hoisted
        - Automatically initialized with undefined

        Example:

            console.log(a); // undefined
            var a = 10;
            console.log(a); // 10

    2. let and const Hoisting

        let and const are also hoisted, BUT:

        ❌ They are not initialized

        This creates something called the: 🔥 Temporal Dead Zone (TDZ)

        Example:

            console.log(x); // ❌ ReferenceError
            let x = 5;

    3. Function Declarations

        Function declarations are fully hoisted.

        greet();

        function greet() {
        console.log("Hello");
        }

        Note: But this doesn't work with Array function

    4. Function Expressions

        Function expressions behave like variables.
        Example using var:

            sayHi(); // ❌ TypeError

            var sayHi = function () {
            console.log("Hi");
            };

        Internally:

            var sayHi;
            sayHi(); // undefined()

        So:

        variable is hoisted
        function value is not

Q) When to use for, while or do while loop?
Ans) 
    1. for Loop

        Use for when:
        - You know how many times the loop should run.
        - You need a counter/index.

        Best Use Cases
        - Iterating arrays
        - Fixed number of repetitions
        - Counting loops

    2. while Loop

        Use while when:
        - You don’t know how many times the loop will run
        - The loop depends on a condition, Here, we don’t know how many attempts the user will take.

        Best Use Cases
        - Waiting for user input
        - Running until some condition changes

    3. do...while Loop

        Example:
        - Showing menu at least once
        - Asking user whether to continue

    function sayBye() {
        console.log("Bye!");

            }, 2000);
        }

        fetchData(function(data) {
            console.log(data);
        });

        2. Timers & Scheduling

            setTimeout(() => {
                console.log("Show popup");
            }, 3000);

        3. Array Operations: Callbacks are heavily used in modern JavaScript array methods.

            const nums = [1, 2, 3];
            const doubled = nums.map(num => num * 2);

Q) What are Promises and Async/Await?
Ans) A Promise is an object that represents: the eventual completion or failure of an asynchronous operation.

    - Why Promises Were Introduced: Before promises, JavaScript mainly used callbacks, which creates Callback Hell

        - Promise States: A Promise has 3 states:

            Pending -	Initial state
            Resolved / Fulfilled - Operation successful
            Rejected - Operation failed

    -- Real-World Example

    function fetchUser() {
        return new Promise((resolve, reject) => {

            setTimeout(() => {
            resolve("User Data");
            }, 2000);

        });
    }

    fetchUser()
    .then(data => console.log(data))
    .catch(err => console.log(err));

    -- Problem with Promises: Even though promises are better, too many .then() chains can still become messy.
    Ex.
        fetchData()
        .then(data => {
            return processData(data);
        })
        .then(result => {
            return saveData(result);
        })
        .then(final => {
            console.log(final);
        });

    To solve this, JavaScript introduced:
    🔥 async/await
        
    Q) What is async/await?

    - async/await is syntactic sugar over promises, It makes asynchronous code look synchronous and cleaner.

    ==> Real Comparison

    - Callback Style ❌

        login(function() {
            getProfile(function() {
                getPosts(function() {
                console.log("Done");
                });
            }); 
        });

    - Promise Style ✅

        login()
        .then(getProfile)
        .then(getPosts)
        .then(() => console.log("Done"));

    - Async/Await Style 🚀

        async function run() {

            await login();

            await getProfile();

            await getPosts();

            console.log("Done");

        }

Q) What is iterator pattern? What are Generators Functions ? What is Yield keywords
Ans) As before in for loops the Array is traverse from left to right, but what if we want to make it customizable

    -- Iterator in JavaScript
        - An iterator is an object having:
            - a next() method
            The next() method returns:
                {
                    value: something,
                    done: true/false
                }

    -- Problem with Manual Iterators

        Writing iterators manually is:
            ❌ verbose
            ❌ difficult
            ❌ repetitive

        To solve this, JavaScript introduced:

    🔥 Generator Functions: A Generator Function is a special function that: can pause and resume execution. It automatically creates iterators, bydefault it also has the next() with done and value.

        - Generator functions automatically return iterators.
        - Special function that can pause/resume execution and creates iterators automatically.

    Simple Example:

        function* numbers() {
            yield 1;
            yield 2;
            yield 3;
        }
        const gen = numbers();

        console.log(gen.next());
        console.log(gen.next());
        console.log(gen.next());
        console.log(gen.next());

        Output:

        { value: 1, done: false }
        { value: 2, done: false }
        { value: 3, done: false }
        { value: undefined, done: true }

    What is yield Keyword?

        yield is used inside generator functions, Pauses generator execution and returns a value temporarily.

        It:
            ✅ pauses function execution
            ✅ returns a value
            ✅ saves function state

    -- Real-World Applications
        Example 1: Infinite Sequences

            function* infiniteCounter() {
            let i = 1;
                while (true) {
                    yield i++;
                }
            }

            const counter = infiniteCounter();

            console.log(counter.next().value);
            console.log(counter.next().value);

        Used in:

            - ID generators
            - pagination
            - streaming

        Example 2: Pagination / Lazy Loading - Instead of loading everything: Load next 10 items only when needed

    ***Now the question arises - Return vs Yield

        Return: Ends function, One-time value, Function terminates
        Yield: Pauses function, Multiple values possible, Function resumes later

Q) What is Debouncing and Throttling in JavaScript?
Ans) Both Debouncing and Throttling are techniques used to: control how frequently a function executes.

Some browser events fire MANY times rapidly:

    Examples:

    - scrolling
    - resizing
    - typing
    - mouse movement

    1. Debouncing

        Debouncing means: Execute function only AFTER a delay once events stop firing.
            - to understand it morw you can draw 2 lines one above the other where below line is the server and above one as client and request starts after one key is pressed and before reaching the server the other key is pressed then the timer will again get restart from 0 and incase the other is not pressed for some fixed amount of time then we will hit the api call

        Simple Meaning
                                "Wait until user stops doing something"

        - Debounce Visualization
        
            Typing...
            Typing...
            Typing...
            (stop)
                ↓
            Function executes ONCE

    Real-World Uses of Debouncing

        ✅ Search bars
        ✅ Auto-save forms
        ✅ Resize events
        ✅ API optimization
        ✅ Input validation

    2. Throttling
    
        Throttling means: Execute function at fixed intervals, no matter how many times event occurs.

        Simple Meaning
                                "Allow execution once every X milliseconds"

    Real-World Uses of Throttling

        ✅ Scroll tracking
        ✅ Mouse movement
        ✅ Game controls
        ✅ Window resizing
        ✅ Rate limiting
        ✅ lazy loading


    ✅ Final Definitions

        🔥 Debouncing: Delays function execution until events stop firing for a specified time.

        🔥 Throttling: Limits function execution to once every specified interval.

Q) What is bind() function?

    🔹 1. Shallow Copy

        copiedUser.address.city = "Delhi";

    🔹 2. Deep Copy

        Nested objects/arrays become:

Q) What is Type Coersion in JavaScript?
Ans) Type coercion in JavaScript is the automatic or implicit conversion of a value from one data type to another (e.g., string to number) to make an operation possible.

- Key Types of Coercion

    1. String Coercion: Occurs primarily with the "+" operator. If any operand is a string, JavaScript converts the others to strings and concatenates them.Example: '5' + 10 results in "510".

    2. Numeric Coercion: Happens with mathematical operators like -, *, /, and %. JavaScript attempts to convert strings or booleans into numbers.Example: '10' - 5 results in 5.Example: true + 1 results in 2 (since true is coerced to 1).

    3. Boolean Coercion: Occurs in logical contexts like if statements or using logical operators (&&, ||, !). Values are coerced to true (truthy) or false (falsy).Falsy values include: false, 0, "", null, undefined, and NaN.
