Q) What if we only want to update the color of our car?

function Car() {
  const [car, setCar] = useState({
    brand: "Ford",
    model: "Mustang",
    year: "1964",
    color: "red"
  });

  const updateColor = () => {
    setCar(previousState => {
      return { ...previousState, color: "blue" }
    });
  }

  return (
    <>
      <h1>My {car.brand}</h1>
      <p>
        It is a {car.color} {car.model} from {car.year}.
      </p>
      <button
        type="button"
        onClick={updateColor}
      >Blue</button>
    </>
  )
}

Q) How to perform clean up in useEffect ?
  -> We can perform cleanup by returning the function which calls a function to disconnect or clear the fetching, timers, timeouts

e.g., 
      useEffect(() => {
          const timeoutId = setTimeout(() => {
            setCounter(counter + 1);
          }, 3000);
      //This is the return function for the clean up activity
          return () => {
            clearTimeout(timeoutId);
          };
        }, [counter]);


3) useMemo - 

As we know when the component get re-render it calls all the functions which comes under the component function, so If we want to avoid running some expensive program then we can useMemo to cache the data and only run when required (By giving the value in the dependency array)
e.g.,

const App = () => {
  const [count, setCount] = useState(0);
  const [todos, setTodos] = useState([]);
  const calculation = useMemo(() => expensiveCalculation(count), [count]);

  const increment = () => {
    setCount((c) => c + 1);
  };
  const addTodo = () => {
    setTodos((t) => [...t, "New Todo"]);
  };

  return (
    <div>
      <div>
        <h2>My Todos</h2>
        {todos.map((todo, index) => {
          return <p key={index}>{todo}</p>;
        })}
        <button onClick={addTodo}>Add Todo</button>
      </div>
      <hr />
      <div>
        Count: {count}
        <button onClick={increment}>+</button>
        <h2>Expensive Calculation</h2>
        {calculation}
      </div>
    </div>
  );
};

const expensiveCalculation = (num) => {
  console.log("Calculating...");
  for (let i = 0; i < 1000000000; i++) {
    num += 1;
  }
  return num;
};

5) useContext - It is used to provide the global state to all of the children from the global provider, as it is a way to manage state globally and it is used to avoid prop drilling.

How to create useContext

  Step 1 - use createContext from react export it 
  Step 2 - Then wrap that component all around to the component who need that value
  Step 3 - Then we can pass the value as an attribute to the wrapped element
  Step 4 - Now we can use value which is passed in all the component using useContext hook

But it has some disadvantages while using it: 

  1. Unnecessary Re-renders: Whenever the context value changes, all consuming components re-render, even if they only use a small part of the state.
  2. Poor Scalability: As the application grows, managing multiple contexts becomes difficult and messy.
  3. Tight Coupling: Components become tightly coupled to specific contexts, making reuse and testing harder.
  4. Frequent State Updates Can Be Expensive: If the state changes very frequently (like real-time updates, forms, animations, websocket data), useContext can cause many re-renders.

6) useCallback -
As we know in react if any of the state changes in component then complete component gets re-rendered, so without useCallback in the parent component even if the function has not changed any of state which is used in the function then also the function gets re-rendered each time the current component get rendered, so just to avoid such re-creation of the function we need to freeze that function thats why we use useCallback().

 useCallback Hook returns a memoized callback function,It is used to freeze the function, so that it can avoid re-rendering
//See the example From the folder PracticeUseReducer
  
  Example without useCallback: 

      const handleClick = () => {
        console.log("Clicked");
      };
      <Child onClick={handleClick} />

      Even if logic is same, handleClick gets recreated every render, so child re-renders.

  Example with useCallback:

    const handleClick = useCallback(() => {
      console.log("Clicked");
    }, []);

    const Child = React.memo(({ onClick }) => {
      console.log("Child rendered");
      return <button onClick={onClick}>Click</button>;
    });

    Using useCallback prevents unnecessary child re-renders

  When to use useCallback:

    1. Passing functions to memoized child components
    2. Preventing unnecessary re-renders

  When to avoid useCallback

    1. Small/simple applications
    2. Functions not passed as props
    3. Overusing it everywhere

------------Rest and Spread Operator------------

-> Rest Operator : The rest parameter syntax allows a function to accept an indefinite number of arguments as an array, providing a way to represent variadic functions in JavaScript, example.,

function myFun(a, b, ...manyMoreArgs) {
  console.log("a", a);
  console.log("b", b);
  console.log("manyMoreArgs", manyMoreArgs);
}

myFun("one", "two", "three", "four", "five", "six");

// a, "one"
// b, "two"
// manyMoreArgs, ["three", "four", "five", "six"] <-- an array


A function definition can only have one rest parameter, and the rest parameter must be the last parameter in the function definition, the below code is not allowed

function wrong1(...one, ...wrong) {}
function wrong2(...wrong, arg2, arg3) {}

-> Spread Operator : The spread (...) syntax allows an iterable, such as an array or string, to be expanded in places where arguments are expected, example.,

function sum(x, y, z) {
  return x + y + z;
}

const numbers = [1, 2, 3];

console.log(sum(...numbers));
// Expected output: 6

var vs let vs const

- var has a function scope, not a block scope: 
	If you use var outside of a function, it belongs to the global scope.

	If you use var inside of a function, it belongs to that function.

	If you use var inside of a block, i.e. a for loop, the variable is still available outside of that block.

- let has a block scope.
	let is the block scoped version of var, and is limited to the block (or expression) where it is defined.

	If you use let inside of a block, i.e. a for loop, the variable is only available inside of that loop.


- const is a variable that once it has been created, its value can never change.const has a block scope.

-- React Memo

React.memo is a Higher Order Component (HOC) used to optimize functional components by preventing unnecessary re-renders.It memoizes the component and re-renders it only when its props change.

Q) Why do we need React.memo?
Ans) In React, when a parent component re-renders, all child components also re-render by default, even if their props have not changed. React.memo helps avoid those unnecessary renders.

Using memo will cause React to skip rendering a component if its props have not changed.

Example.,

  const Child = React.memo(({ name }) => {
    console.log("Child Rendered");

    return <h1>{name}</h1>;
  });

//Before when memo was not used the Child component gets rendered each time when the parent component gets rendered

Q) How it works internally
Ans) React.memo performs a shallow comparison of previous props and new props.

      - If props are the same:

        React skips re-rendering

      - If props changed:

        component re-renders

Q) When to avoid React.memo
Ans) 1. Small or Simple Components: For lightweight components, memoization overhead may be unnecessary.
    2. Props Changing Frequently: If props change on every render, React.memo gives no benefit.
    3. Overusing Optimization: Using React.memo everywhere can make code more complex and sometimes even reduce performance.
