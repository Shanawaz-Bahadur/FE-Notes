3. Recurrent Neural Network(RNN)

    Before RNNs, traditional neural networks treated every input independently as it is done in ANN.
    The one of the most important feature of RNN is ,it remembers previous information while processing the sequence.

        In RNN introduces a hidden state (memory): It remembers previous information while processing the sequence.

            Word1 → Memory
                ↓
        Word2 → Updated Memory
                ↓
        Word3 → Updated Memory

    Example

        Input:
            I love AI

        When processing "AI", the network has already seen:
            I
            love

    - Problem with RNN

        Vanishing Gradient Problem(the difficulty of training the network to remember long-term patterns.)

        Suppose:
            The food at the restaurant was amazing because ...

        - The model may need information from words far back in the sentence.
        - RNN struggles to remember long-term dependencies.
        - Information gradually fades.

4. LSTM (Long Short-Term Memory) - It is an imporved version of RNN

    Remember long-term information, and decide what to forget and what to keep 

    LSTM has 2 types of memory:

        1. Cell State (Lond-term memory)
        2. Hidden State (Short-term memory)

    Q) Why was LSTM introduced?
    Answer: To solve the vanishing gradient problem and improve long-term memory retention.

5. Encoder-Decoder Architecture

    Problem:
        Input length and output length can differ.
        Traditional RNNs struggled with this.

    Solution: Encoder-Decode(Two networks)
        - Encoder
            1. Reads input
            2. Converts it into a context representation.

        - Decoder
            1. Uses that representation.
            2. Generates output.

    - Flow
    
        Input Sentence
            ↓
        Encoder
            ↓
        Context Vector
            ↓
        Decoder
            ↓
        Output Sentence

    Problem
        - Everything is compressed into one context vector.
        - Important information gets lost.

    Interview Question
    Q) Why Encoder-Decoder?
    Answer: To support sequence-to-sequence tasks like translation where input and output lengths differ.

6. Transformer: Attention Mechanism

    This is the major breakthrough.

        Researchers realized:
            Why force the decoder to rely on only one compressed vector?

        Instead:
            Let the decoder look back at important words whenever needed.

    Published in the famous paper in 2017
        ***Attention Is All You Need

    --> Biggest Idea

        Remove:
            - RNN
            - LSTM

        and use only ***attention.

    Q) Why?

        --> RNN processing(Sequential):

            Word1
              ↓
            Word2
              ↓
            Word3
              ↓
            Word4

            Cannot process all words simultaneously.

        --> Transformer:

            Word1
            Word2
            Word3
            Word4

            Processed in parallel, Much faster.

7. Self-Attention

    This is the heart of Transformers, Every word can look at every other word.

    Foundation of Modern LLMs

        - GPT
        - Claude
        - Gemini
        - Llama

        all rely on Transformers.

8. Encoder vs Decoder in Transformers

    Transformer originally contains both:

        1. Encoder: Used for understanding text.
            Examples:
            - Search
            - Classification
            - Embeddings

                Models like: BERT

        2. Decoder: Used for generating text.
            Examples:
            - Chatbots
            - Content generation
            - Code generation

                Models like: GPT

    Q) Why did we move from RNN → LSTM → Transformer?
    Ans) 
        - RNN introduced memory for sequential data but struggled with long-term dependencies.
        - LSTM solved the vanishing gradient problem and improved long-term memory retention.
        - Encoder-Decoder enabled sequence-to-sequence tasks such as machine translation.
        - However, encoder-decoder models compressed information into a fixed context vector, which became a bottleneck.
        - Attention allowed models to focus on relevant parts of the input dynamically.
        - Transformers replaced recurrence with self-attention, enabling parallel processing, better context understanding, faster training, and scalability.
        - Modern LLMs like GPT and Claude are built on Transformer architectures.

Q) What is RAG Evaluation: Precision, Recall, Faithfulness, RAGAS ?
Ans) In RAG the 2 most important aspects is 

        1. Retrieval(***Retrieved Context - mainly depend on Embedding models used) and 2. Generation(***Generated Answer - mainly depend on LLM model used)

    - Comparing answer with Query(Embedding based)

    Precision - How much of the retrieved context/chunks is relevant?

                Precision = relevant chunks / Total Retrieved chunks

    Recall - How much of the relevant information was retrieved?

                Recall = retrieved relevant chunks/total retrieved chunks

    Answer Relevance - How well does the answer address the question? or How much relavant is the answer to the question?

    - Comparing Generated response with retrieved context(Deep Reasoning)

    Faithfulness - How well the Generated answer is fully supported by the retrieved Context or it has generated the response on its own - Bad Faithfulness(Hallucination)

    Groundedness - How well the Generated Answer used retrieved context instead of relying on the models internal memory

    ***Note : In practice computing all the above metrics is sometime not possible, so in place of this we can make use of LLM-as-a-Judge

        Here LLM act as an evaluator it reads 3 things, 1. Query, 2. Retrieved Context, 3. Generated Answer
        And provide us all the metrics like Faithfulness, Groundedness, Relevance

    To make all of this standardize we have a framework called - RAGAS(Open source framework for RAG Evaluation) - Internally it used Embedding and LLM-as-as-judge concept to evaluate the RAG system

    For we need to provide 4 things -

        1. Query
        2. Ground truth
        3. Answer - to Evaluate (Response from LLM)
        4. Context - to Evaluate (Retrieved context/chunks from document)

    Note: RAGAS is used only in development phase not in the production, for production we can make use of Trulens(As in production we can have any query and we cannot provide the ground truth)

        - only returns validated, compliant outputs

Q) What is Langgraph
Ans) 
    - LangGraph is an orchestration framework for building intelligent, stateful, and multi-step LLM workflows.
    - It enables advanced features like parallelism, loops, branching, memory, and resumability - making it ideal for agentic and production-grade Al applications.
    - It models your logic as a graph of nodes (tasks - it can be a simple python function) and edges (routing) instead of a linear chain.

Q) What are Workflow?
Ans) 
    - LLM workflows are a step by step process using which we can build complex LLM applications.

    - Each step in a workflow performs a distinct task - such as prompting, reasoning, tool calling, memory access, or decision-making.

    - Workflows can be linear, parallel, branched, or looped, allowing for complex behaviours like retries, multi-agent communication, or tool-augmented reasoning.

    There are multiple types of workflows which are:

        1. Sequential workflow
        2. Parelled workflow
        3. Conditional workflow (branching)
        4. Iterative workflow

Q) What are states in LLM workflow
Ans) In LangGraph, state is the shared memory that flows through your workflow - it holds all the data being passed between nodes as your graph runs.

Q) What are Reducers?
Ans) Reducers in LangGraph define how updates from nodes are applied to the shared state.
    Each key in the state can have its own reducer, which determines whether new data replaces, merges, or adds to the existing value.

Q) Langgraph workflow Execution model
Ans) 
    1. Graph Definition
        You define:
            . The state schema
            . Nodes (functions that perform tasks)
            . Edges (which node connects to which)

    2. Compilation
        You call .compile() on the StateGraph.
        This checks the graph structure and prepares it for execution.

    3. Invocation
        You run the graph with .invoke(initial_state)
        LangGraph sends the initial state as a message to the entry node(s).

Q) What is an LLM?
Ans) A Large Language Model (LLM) is a deep learning model trained on massive amounts of text data to understand and generate human-like language.

    LLMs are built on the Transformer architecture and learn patterns, relationships, grammar, reasoning capabilities, and domain knowledge from training data.

Q) On which architecture does an LLM work?
Ans) Modern LLMs are built on the Transformer architecture, where self-attention enables the model to understand contextual relationships between tokens and generate coherent outputs.

Q) If an LLM is only predicting the next token, then how can it answer user questions?
Ans) An LLM only predicts the next token mathematically, but because it has learned language, facts, and reasoning patterns from massive training data, next-token prediction emerges as question answering, coding, summarization, and reasoning capabilities.

Q) Will Top-K and Top-P work if Temperature is set to 0?
Ans) Top-K and Top-P are sampling techniques. When temperature is set to 0, generation becomes nearly deterministic and behaves like greedy decoding. Since there is no meaningful sampling occurring, Top-K and Top-P usually have little or no practical effect on the generated output.

Q) What is tokenization?
Ans) Tokenization is the critical first step in large language models where raw text is broken down into smaller, manageable chunks called tokens. Since LLMs are mathematical engines that only understand numbers, tokenization translates human language into a sequence of unique numerical IDs

    Tokens are the smallest units of text processed by an LLM.

    Production Example

    If an LLM supports 128k tokens, both prompt and response must fit within that limit.

Q) What is Context Window?
Ans) A context window is the maximum number of tokens an LLM can process in a single request.

    It includes:

        Input Tokens
                +
        Conversation History
                +
        Retrieved Documents
                +
        Output Tokens

    Example

        If the model has: 128k context window
        and the prompt uses: 100k tokens
        then only around: 28k tokens remain for output.

    Why Important?
        Large context windows help with:
            - Long conversations
            - RAG applications
            - Document analysis

Q) What is Temperature?
Ans) Temperature controls the randomness of the model's output.

    Lower temperature: 0.0 - 0.3
        - More deterministic
        - More factual
        - Less creative

    Higher temperature: 0.7 - 1.5
        - More creative
        - More diverse
        - Less predictable

    Production Usage:
        Code Generation: 0 - 0.2
        Content Writing: 0.7 - 1.0

Q) What is Top-P?
Ans) Top-P (Nucleus Sampling) controls token selection by choosing from the smallest set of tokens whose cumulative probability reaches P(Parameter set for the LLM).

    Temperature controls randomness, while Top-P controls how many likely token candidates the model can choose from, it is not same as top-k as in top-k we have fixed number of outputs

Q) What is Hallucination?
Ans) Hallucination occurs when an LLM generates information that sounds plausible but is incorrect, fabricated, or unsupported by facts.

    Mitigation Techniques
        - RAG
        - Function Calling
        - Grounding with external data
        - Validation pipelines
        - Human review

Q) What is Prompt Engineering?
Ans) Prompt Engineering is the process of designing and optimizing prompts to guide an LLM toward producing accurate, relevant, and consistent outputs.

    Prompt engineering involves:

        . Providing clear instructions
        . Giving context
        . Defining constraints
        . Specifying output format
        . Including examples when needed

    - Zero-Shot Prompting: In Zero-Shot Prompting, we ask the model to perform a task without providing any examples.
        Example
            Translate the following sentence into French: "I love artificial intelligence."

    - Few-Shot Prompting: Few-Shot Prompting improves performance by providing example input-output pairs that demonstrate the expected behavior.

        Example
            - Input: Great service
            - Sentiment: Positive

            - Input: Terrible experience
            - Sentiment: Negative

            - Input: Product quality is amazing
            - Sentiment:

        Use Cases
            - Classification
            - Data extraction
            - Domain-specific tasks
            - Custom formatting

    - Role Prompting: Assigning a role or persona to the model.

        Example
            Act as a Senior React Architect.
            Explain Redux Toolkit to a junior developer.
        
    - Chain of Thought (CoT): Encouraging the model to reason through intermediate steps before producing the final answer. Chain of Thought Prompting improves reasoning by asking the model to generate intermediate reasoning steps before arriving at the final answer.

        Example
            A train travels 60 km in 1 hour.
            How far will it travel in 5 hours?
            Think step by step.
        
        Model
            Distance per hour = 60 km
            Time = 5 hours
            Distance = 60 × 5
            Answer = 300 km

    - ReAct Pattern (Reason + Act): ReAct combines reasoning and tool usage, allowing an agent to think, perform actions, observe results, and continue reasoning until the task is completed.

        Example
            User:
                What's the weather in Mumbai today?

            Agent:
                Thought:
                I need weather information.

                Action:
                Call Weather API

                Observation:
                31°C, Cloudy

            Final Answer:
                The current temperature in Mumbai is 31°C and it's cloudy.

    - Structured Prompting: Organizing prompts into clearly defined sections. Structured Prompting reduces ambiguity by clearly separating instructions, context, constraints, and expected output format.

        Example
            Task:
                Extract customer information.

            Input:
                John Smith
                john@gmail.com

            Output Format:
                {
                    "name": "",
                    "email": ""
                }

    - Output Formatting: Explicitly instructing the model how the response should be formatted.

        Example
            Instead of:
                John is 25 years old and lives in Mumbai.

            Return:
                {
                    "name": "John",
                    "age": 25,
                    "city": "Mumbai"
                }

Q) What are Embeddings?
Ans) Embeddings convert text into numerical vectors that capture semantic meaning, enabling similarity search.

    Example:
        "Car"
            and
        "Automobile"

        have different words but similar embedding vectors.

    Q) Why Needed?
        Similarity search operates on embeddings.

            Without embeddings: Keyword Search
            With embeddings: Semantic Search

Q) What is Chunking?
Ans) Chunking is the process of breaking large documents into smaller pieces before generating embeddings to improve retrieval accuracy.

Q) What is Chunk Overlap?
Ans) Chunk overlap preserves contextual continuity by repeating portions of adjacent chunks.
    Benefits
        - Preserves context
        - Better retrieval
        - Reduced information loss

Q) What is Retrieval?
Ans) Retrieval is the process of finding the most relevant chunks for a user query.

    Example:

        User:
            What is Redux Toolkit?

        System:
            - Convert query to embedding
            - Search vector DB
            - Retrieve relevant chunks
        
        Goal
            - Only send relevant information to the LLM.

Q) What is Similarity Search?
Ans) Similarity search finds vectors closest to the query embedding.

    Example:

        Query:
        "state management in React"

        Retrieved:
        Redux Toolkit document - because vectors are close in semantic space.

        Most common metrics:

            - Cosine Similarity
            - Dot Product
            - Euclidean Distance

Q) What is Re-ranking?
Ans) Re-ranking is a second-stage ranking process applied after retrieval.

        Vector Search
            ↓
        Top 20 Chunks
            ↓
        Re-ranker Model
            ↓
        Best 5 Chunks
            ↓
        LLM

    Why Needed?
        - Vector search may return approximately relevant chunks, Re-rankers improve precision.

Q) What is Hybrid Search?
Ans) Hybrid Search combines: Hybrid Search combines semantic vector search and keyword search to improve retrieval accuracy.
        Vector Search
            +
        Keyword Search

    Example:

        User: Error code 5001

            - Embedding search may struggle.
            - Keyword search finds exact error code
            - Combined result is better.

        Benefits:
            - Semantic matching
            - Exact keyword matching
            - Better enterprise search

Q) What is Metadata Filtering?
Ans) Metadata filtering narrows search results before or during vector search.

    Example Metadata:
        {
            "department": "HR",
            "year": 2025,
            "region": "India"
        }

    User asks:
        Show HR policies for India.

    Filter:
        {
            "department": "HR",

Q) Users complain that RAG responses are missing important information from PDFs.
Ans) I would investigate:

        - Chunk size
        - Chunk overlap
        - Embedding model quality
        - Retrieval top-k value
        - Document parsing issues
        - Re-ranking effectiveness

    Most commonly, context is lost due to poor chunking or insufficient overlap.

Q) Your RAG system retrieves irrelevant documents despite good embeddings.
Ans) Possible solutions:

        - Introduce re-ranking
        - Improve chunking strategy
        - Tune Top-K retrieval
        - Evaluate embedding model

    Often retrieval is broad but not precise, so re-ranking significantly improves results.

Q) A user asks: What was the leave policy in 2024? but the system retrieves 2025 documents.
Ans) How would you solve this?
    Expected Answer: Use metadata filtering.

Q) Users search for exact product IDs and retrieval quality is poor.
Ans) Expected Answer: Vector search is optimized for semantic similarity, not exact identifier matching.
    Example:
        PROD-12345

    Solution:
        - Hybrid Search
        - Keyword Search
        - BM25

Q) Your RAG system retrieves relevant chunks, but answers are still incorrect.
Ans) Expected Answer

        Several possibilities:

            - Retrieved chunks exceed context window.
            - Poor prompt design.
            - Retrieved context not passed correctly.
            - LLM ignores retrieved context.
        I would inspect the final prompt being sent to the LLM.

Q) Why not simply increase chunk size to 5000 tokens?
Ans) Expected Answer

        Large chunks create multiple issues:
            - More noise
            - Lower retrieval precision
            - Higher token costs
            - Context dilution
        Smaller semantically meaningful chunks generally retrieve more accurately.

Q) When would you use Re-ranking?
Ans) Expected Answer: When initial vector retrieval has high recall but low precision.

        Example: Vector search returns 20 potentially relevant chunks.
        Re-ranking helps identify the most relevant 5 before sending them to the LLM.

Q) How would you reduce hallucinations in a RAG system?
Ans) Expected Answer
        I would:

            - Improve retrieval quality
            - Use metadata filtering
            - Add re-ranking
            - Use high-quality embeddings
            - Ground answers only on retrieved context
            - Ask the model to say "I don't know" when context is insufficient
            - Add citations/sources

Q) Users report that answers are irrelevant. What would you debug first?
Ans)
    Step 1: Verify Retrieved Chunks - The first thing I'd check is:
        Are the retrieved chunks actually relevant to the user's question?
    If retrieval itself is wrong, the LLM cannot generate a good answer.

    Step 2: Check Chunking Strategy
    Questions I'd ask:

        - Is chunk size too large?
        - Is chunk size too small?
        - Is context split across chunks?
        - Is chunk overlap sufficient?

    Step 3: Evaluate Embeddings
        I would verify:
            - Which embedding model is being used?
            - Does it perform well on our domain?

    Step 4: Review Retrieval Strategy
        I'd inspect:
            - Top-K value
            - Similarity threshold
            - Hybrid search usage
            - Re-ranking effectiveness

    Step 5: Check Metadata Filters - Sometimes overly restrictive filters remove relevant documents.

Q) Hallucinations increased after deployment. How would you investigate?
Ans) 
    Step 1: Compare Before vs After Deployment
        I would investigate:
            - Was embedding model changed?
            - Was chunking strategy changed?
            - Was retrieval pipeline modified?
            - Was prompt updated?

    Step 2: Verify Retrieval Quality
        Questions:
            - Are relevant chunks still being retrieved?
            - Has retrieval precision dropped?
        Poor retrieval often appears as hallucination.

    Step 3: Review Prompt

        I would inspect whether the prompt contains instructions such as:
            Answer only from provided context.
            If information is unavailable, say "I don't know."

    Step 4: Check Context Window Usage
        Possible issue:
            Retrieved Context = 20,000 tokens
            Important chunks may be truncated.

    Step 5: Review Temperature
        If temperature was increased:
            0.2 → 0.8
            hallucinations may increase.

Q) Two very similar questions retrieve completely different documents.
Ans) This indicates a retrieval consistency issue - I would compare query embeddings, retrieval scores, metadata filters, chunk boundaries, and similarity thresholds. If needed, I would introduce hybrid search and re-ranking to improve retrieval consistency.

    Example
        Question 1:
            What is the leave policy?

        Question 2:
            Explain employee leave rules.
        Different results appear.

Ans) This is a generation-stage problem rather than a retrieval problem - If retrieval is correct but answers are wrong, I would inspect prompt design(Answer only using the provided context. If the answer is not present, say "I don't know."), context truncation, chunk ordering, temperature settings, and grounding instructions. In many cases, the model is not effectively using the retrieved context even though retrieval itself is working correctly.

----------------------------------Embeddings

Q) What are Embeddings?
Ans) Embeddings convert text into numerical vectors that preserve semantic meaning, enabling similarity-based retrieval.

    The goal is to place semantically similar text close together in vector space.

        Example:
            - Car
            - Automobile
            - Vehicle
        Although these words are different, their embeddings will be close to each other.

        While:
            - Car
            - Pizza
            - Football
        will be far apart.

        Example
            Text:
                React is a frontend library.

            Embedding:
                [0.12, -0.44, 0.82, 0.19, ...]     The actual numbers aren't important, What matters is the relative position in vector space.

Q) What are Semantic Search?
Ans) Semantic search retrieves documents based on meaning rather than exact keyword matching.

    Traditional Keyword Search

        Query:
            How do I reset my password?

        Document:
            Steps to change account credentials.

        Keyword search may fail because:
            password ≠ credentials

    Semantic Search

        Embeddings understand that:
            - password
            - credentials
            - login information

        are semantically related, So retrieval succeeds.

Q) What are Embedding Models?
Ans) Embedding models generate vector representations of text and must remain consistent between indexing and querying.

    Examples include:

        - OpenAI Embeddings
        - Sentence Transformers
        - BGE Models

    Each model differs in:

        - Accuracy
        - Latency

Q) The same query retrieves unrelated chunks.
Ans) Unrelated retrieval can result from poor chunking, embedding quality issues, incorrect similarity metrics, missing metadata filters, weak thresholds, or the absence of re-ranking. I would inspect retrieval scores and evaluate each stage of the retrieval pipeline systematically.

Q) Can embeddings understand synonyms?
Ans) Yes. Because embeddings capture semantic meaning, words such as "car" and "automobile" are typically placed close together in vector space even though they are different keywords.

Q) Why can't we use keyword search alone instead of embeddings?
Ans) Keyword search depends on exact word matches and often fails when users phrase questions differently. Embeddings enable semantic search by retrieving documents based on meaning rather than exact terms, which significantly improves retrieval quality in RAG systems.

Q) How do you select an embedding model for a use case?
Ans) The best embedding model is the one that performs best on your data and retrieval tasks, not necessarily the one with the highest benchmark score.

    I select an embedding model based on:

        - Domain of the data: The first factor I consider is whether the data is general-purpose or domain-specific because domain-aligned embeddings often improve retrieval quality.

        - Retrieval quality requirements
        - Latency requirements
        - Cost constraints: At enterprise scale, embedding generation and storage costs become important factors when selecting a model.
                Need to consider:

                    . Token pricing
                    . Re-indexing cost
                    . Storage cost

        - Multilingual support: User queries may come in(English, Hindi, Arabic, French), the embedding model must support multilingual retrieval.
        - Embedding dimensions size: I evaluate embedding dimensions because larger vectors may improve retrieval quality but increase storage and search overhead. Higher dimensions often:

            - Capture richer semantics
            - Require more storage
            - Increase search costs

        - Benchmark performance
        - Deployment requirements

Q) You are building a RAG system for an internal HR portal.
Ans) I would first gather representative HR queries and documents, then evaluate a few candidate embedding models on retrieval metrics such as Recall@K. Since HR documents are mostly natural language, a strong general-purpose embedding model would likely be sufficient. I would also evaluate latency, cost, multilingual support, and storage requirements before making the final selection.

Q) You changed the embedding model. What should you do before deployment?
Ans) Since each embedding model creates a different vector space, I would re-embed the entire document corpus, rebuild the vector index, validate retrieval quality using benchmark queries, and compare metrics against the previous model before deploying.

-----------------------------------------Vector Databases

Q) Why do we need a Vector Database?
Ans) A Vector Database is designed to efficiently store, index, and search high-dimensional embedding vectors.

    Without a Vector DB:

        Query Embedding
            ↓
        Compare Against Every Vector
            ↓
        Find Similar Documents

    This becomes extremely slow when dealing with millions of vectors.Brute-force comparison against every vector would be computationally expensive.

    A Vector DB uses specialized indexes to perform Approximate Nearest Neighbor (ANN) search efficiently.

    What does a Vector DB provide?

        - Vector Storage
        - Similarity Search
        - Metadata Filtering
        - Indexing
        - Scalability
        - Fast Retrieval

Q) What is Similarity Search?
Ans) Similarity Search retrieves vectors that are closest to the query vector.
    Process:

        User Query
            ↓
        Embedding Model
            ↓
        Query Vector
            ↓
        Vector Search
            ↓
        Top-K Similar Vectors

    Example

        Query:
        How can I reset my password?

        Retrieved document:
        Steps to change account credentials.

        - Although keywords differ, embeddings are semantically similar.

Q) Why not store embeddings in a relational database instead of a vector database?
Ans) Relational databases are optimized for exact lookups and structured queries, whereas vector databases are optimized for nearest-neighbor search on high-dimensional embeddings. As data grows to millions of vectors, vector databases provide significantly better retrieval performance through ANN indexing techniques.

Q) What's the biggest mistake people make with Vector Databases?
Ans) Treating vector search as the entire retrieval solution. In production systems, vector search is usually combined with metadata filtering, re-ranking, and sometimes hybrid search to achieve high retrieval quality.

--------------------------------- AI Agents

Q)What is Agentic Al? How is it different from Generative Al?
Ans) 
    Generative AI -> models that generate content (text, images) in response to a prompt - reactive, stateless, one-shot.
    Agentic Al -> systems built on top of these models that autonomously pursue goals through multi-step reasoning and action. An agent perceives its environment, reasons about actions, uses tools, observes results, and iterates until the goal is achieved.

    Simple: GenAI answers. Agentic Al acts.

    Example: GenAI writes a marketing plan. An agent researches the market, writes the plan, emails stakeholders, and schedules a review meeting - autonomously.

Q) Explain the ReAct framework with an example.
Ans) ReAct = Reasoning + Acting. 

    Each cycle: Thought (internal reasoning) -> Action (tool invocation) -> Observation (result). Loop continues until task is complete.

    Example: Task = 'Compare Delhi vs Tokyo population.' 
            Agent Thinks: 'Search Delhi first.' 
            Acts: web_search(). Observes: 32M. 
            Thinks: 'Now Tokyo.' 
            Acts: web_search(). Observes: 37.6M. Calculates difference. Done.

    Key advantage: Each step grounded in real observations - reduces hallucination vs one-shot generation.
